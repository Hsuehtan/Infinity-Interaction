## 1. 目标与范围

让创作者把人物、场景、音色、道具保存为可复用的项目参考资产，减少下载、重新上传和重复选择。核心路径为：

1. 上传或选择项目素材 → 建立设定 → 生成视频时显式选择其中的文件。
2. 工坊文字生图或参考图生图 → 结果进入素材库 → 明确“存为设定” → 再用于生成。
3. 设定页“生成设定图片” → 直接进入普通 AI 工坊，不携带设定表单或编辑器目标、不切换输出类型 → 后续按普通工坊操作。

本期包含四种设定、多文件、独立工坊图片生成、结果快捷新建设定和手动选择设定文件作为输入。生成仅使用当前项目、作者明确填写的参数与选定文件，不捕获或绑定编辑器 scene/clip，也不锁定“当前选择”。结果只入项目素材库；采用时由作者手动选择目标，保留指纹、revision、权限与幂等校验。不包含 AI 编剧/玩法、自动创建设定、音频生成/配音/声音克隆、跨项目设定库或批量整章生产；不承诺多图/多镜头外观绝对一致。

S1 保留 14 个追溯编号，其中 T67/T68 已撤销，12 项有效任务按五个交付包推进：设定库 T64–T66、图片服务 T69–T73、工坊图片 T74、衔接 T75–T76、收尾 T78。发布隔离由 M4 T50/T57 验收，不作为 T78 前置。设定撤销/导入导出保留，设定关系和表单草稿不恢复；本次不新增文件容量限制。

视频仍可直接使用工坊的图片/视频/音频参考，不要求所有素材先成为设定。视频参考继续由现有工坊承接，本轮不增加“视频设定”分类。音色文件作为输入参考，不等于产品获得了声音克隆能力。

## 3. 设定实体与文件

### 3.1 字段

| 字段 | 要求 |
| --- | --- |
| 名称 | 必填，去除首尾空白后非空；名称允许重复，身份依靠 ID |
| 简介 | 必填，去除首尾空白后非空；由作者编写，不自动补写 |
| 主体文件 | 至少一个，允许多个；必须是同项目、已核验 ready 的 Asset，不保存临时 URL 作为身份 |
| 分类 | 人物 person、场景 scene、音色 voice、道具 prop；创建时选择 |
| 类型扩展字段 | 公共基础之上按分类校验的扩展槽；本轮不添加未确认的年龄、地点等业务字段，也不提供自定义字段设计器 |
| 系统信息 | 稳定设定 ID、projectId、schemaVersion、变更版本/时间；来源文件在 Asset/Job 中追溯 |

人物、场景、道具只接收图片；音色只接收音频。前端筛选和服务端验证一致，不能靠扩展名判定；读取 MIME、实际解码和媒体元数据。名称/简介沿用项目文本安全上限；文件上传沿用媒体服务限制，不把某个供应商的一次请求限制变成设定库上限。

**多文件不等于一次全部生成。** 保存设定与生成请求分别校验；一个设定可包含超过单次模型输入数量的文件，作者选取子集后再按模型能力校验。现有 `assetIds.max(20)` 不应未经说明沿用为新的产品上限；实施时移除该任意业务上限，使用可见的项目存储配额、分页和单次命令批量限制保护资源，不静默截断已有文件。

### 3.2 编辑与展示

- 分类列表展示名称、简介摘要、缩略图/音频标识、文件数；详情支持全部图片预览和逐条音频试听，不自动播放音频。
- 允许上传、选择已有项目素材、添加多个文件和移除引用。相同 assetId 在一个设定中不重复加入。文件展示按保存顺序，首项可作列表预览；不新增“主文件审批”或自动选择所有文件的行为。
- 新建或补齐后的完整设定不能保存为空简介或零文件；未保存表单仅保存在当前弹窗内存中；取消、关闭、跳转或刷新均丢弃，不持久化或提供恢复。移除最后一个文件时要求先补入文件或明确删除整个设定。
- 上传失败/处理中保留表单并说明原因；有未就绪文件时不得悄悄忽略它后显示保存成功。取消新建不删除已成功入库素材，素材库仍可找到。
- 删除设定需确认；只删除该设定，不级联删除其他设定、素材、故事、时间线或生成任务。被设定/请求/任务/历史引用的文件沿用归档保护。
- 新增、编辑、删除、文件引用变化均经项目命令，支持幂等、revision 校验、撤销/重做；只看详情或试听不推进工程 revision。

### 3.3 旧数据

新约束不能全局套在旧项目的每次保存校验上。现有缺简介、零文件、混合模态或超出新分类要求的记录保留 ID、原文和 assetIds，显示“待补齐/待整理”；不阻止无关的场景编辑、撤销、导入或项目打开。

- 旧 `other` 保留在“其他（历史资料）”，不自动改为道具，不丢弃；作者可明确选择分类并补齐。
- 旧资料允许继续保存文字修改而保持待补齐，直到作者明确完成补齐。此兼容豁免只由迁移来源确定，客户端不能伪造 legacy 状态绕过新建校验。
- 从设定入口引用时，仅完整且媒体有效的设定可用；旧资料内的有效文件仍可从素材库单独选用。
- 导入、导出、命令历史与恢复数据保留新增分类及文件引用；旧关系元数据按下节忽略，不恢复关系功能。迁移可重复执行且有备份，不能重写旧发布版本。

## 5. 独立 AI 工坊图片生成

普通工坊提供生成与历史能力，生成快捷入口统一进入普通工坊。T79 已完成本地入口与旧 UI 状态清理；输入及编辑属性保持可达，已有会话、任务和素材继续保留。未发送输入按 2026-10-05 简化决定不持久化。

### 5.1 输出类型与输入模式

普通工坊使用 `outputKind=image|video`、项目会话、组件内输入、请求、任务和统一素材。图片支持**文字生图**与**参考图生图**，视频沿用当前已批准模式；只接受模型支持且作者明确选择的模态，不把音频/视频塞给图片接口，不从编辑器选中对象补入素材或生成目标。

- 当前工坊内切类型时共享提示词，并分别保留模型、参数和参考素材；离页或刷新后丢弃。不得把视频时长、音频引用或计价参数误传图片接口，也不得改变已存在请求卡和运行任务。
- 图片输入展示描述、所选参考图，以及适配器实际支持的尺寸/画幅等设置；不显示假支持的参数。首版按一次请求一个目标图片结果验收，不增加批量生成管理；多文件设定可通过多次生成或上传形成。
- 发送只创建消息与请求卡，确认才创建唯一任务并提交。请求卡列出输出类型、模型、完整有效描述与参考文件，不能仅显示“同上”；消耗展示及账务按 09 的内置预估/个人免计价模式，新任务不沿用历史额度预留。
- 参考图修改、模型更换或内置模型预估失效需要新的明确确认；个人模型不因缺报价受阻。图片模型未配置或不支持参考图时明确禁用该操作，视频生成、上传设定继续可用。
- 图片失败、安全重试、取消、未知提交、入库失败沿用现有持久任务原则；同步返回图片的服务也先经过 Job，不能通过浏览器直调绕过权限和账本。

### 5.2 模型与默认配置

图片生成依赖明确的协议实现及服务端能力声明，不能由聊天/视频模型名称推断。T69 的首次两模式核验作为历史证据保留；后续供应商/模型配置、JSON 请求模板、代码适配器及来源切换按 07/08 与 G/R/J/B/MR 增量执行，不恢复“只接一个模型”的旧限制。复用现有任务、素材、私有访问及安全保障，不绕过确认、权限、幂等或媒体核验。

模型选择、能力目录和配置所有权按 08 的内置/个人双模式；任务固定确认时的连接、协议和凭据版本，不能因为默认或编辑器选择变化重定向既有任务。平台密钥不向创作者泄漏，个人配置不越权读取他人凭据。

消耗语义按 09：新内置任务仅展示预估，个人模型不计价，两者不创建旧额度预留/资金流水；历史账务与参数快照继续按原模式读取。功能上不再用旧项目额度拦截新模式，测试授权上仍不能擅自发起新的付费请求或复用旧 M2 预算。

### 5.3 结果与历史

图片与视频使用同一历史和素材库，提供媒体类型筛选、预览、输入追溯、来源、状态及重试；图片有授权下载入口。实际解码核验格式、像素、字节上限并写入私有存储后才 ready；拒绝伪装文件、损坏图片及主动内容，防范解码资源超限。

每个结果使用稳定 Asset ID；如供应商回执附带多个文件，入库身份按 Job＋结果项去重，不重发生成。首版界面不承诺批量数量选项。生成成功只入素材库，既不自动插入时间线，也不自动新建/覆盖设定。

## 6. 从生成结果快捷创建设定

图片结果卡“存为设定”打开轻量表单：分类（人物/场景/道具）、名称、简介、主体文件（已带入该结果，可增选同项目图片）。空值需作者补齐；只有明确保存才建立设定和文件引用，不复制文件。

- 同一保存操作重传/双击通过 commandId 返回同一设定；作者主动再次新建可以把同一素材用于另一个设定，不因 Job 已用过就禁止复用。
- 保存后提供“查看设定”；撤销只撤销设定创建，不撤销任务、素材入库或供应商费用。
- “生成设定图片”关闭表单后进入普通工坊，不携带分类、名称、简介、用途或 scene/clip，不修改普通工坊当前输入和输出类型。
- 不提供返回设定草稿、保留/切换设定图片草稿或用途横幅。历史已冻结请求仍可兼容读取，但新请求不再产生设定用途字段。
- 音色新建仅提供上传/选择音频，不提供会误导为音色生成的按钮。本轮不做“把结果自动追加到已有设定”；作者可以通过设定编辑器选择已生成素材来添加。

## 7. 引用设定参与生成

普通工坊在参考素材选择器提供“从设定选择”，不另建生成路径。作者先选设定，再明确勾选文件；媒体卡显示设定名称、文件预览和用途/角色，仅使用作者明确选择的媒体输入。按 CN 使用素材缩略图和稳定 Asset 身份，不恢复 `@` 插入/新请求解析；多参考图能力按 MR，顺序变动保持文件对应关系。

- 图片生成仅展示可用图片；视频按当前模式支持的首/尾帧或图片/视频/音频参考校验。音色在视频支持音频参考的模式下可选；不兼容输入明确说明，不能静默丢弃或转换模态。
- 仅发送明确选择的文件和确认卡列出的文本；简介可由作者显式加入有效描述，不默认把所有简介或项目资料外发。
- `referenceSnapshot` 固定设定 ID/版本、显示名称、选中文件 ID/摘要和明确纳入的文本。设定之后改名、换文件或删除，不改写历史请求/任务输入。
- 待确认卡若所引用设定被删除或相关版本已变化，提示差异并要求重新选择/确认；其他设定变化不使无关卡失效。已提交任务继续使用被冻结且仍受引用保护的 Asset，不读取最新设定。
- 向供应商只传必要媒体和有效描述，不传凭据、对象存储键或完整项目。实际发送量受生成能力/资源限制。
- 新生成不持有 scene/clip 目标；历史 `context` 及既有请求/任务/参数只兼容读取，不迁移删除或挪用为新输入目标。结果手动采用时重新明确目标，仍执行片段指纹、revision 和 commandId 幂等检查。

## 8. 技术契约与实施结构

### 8.1 公共基础＋分类扩展

不建设四套重复 CRUD，也不把分类差异压成任意 JSON。使用公共基础、带判别字段的类型和独立校验器，未来字段在对应类型扩展。示意契约（不是已经存在的代码）：

```ts
type ReferenceKind = 'person' | 'scene' | 'voice' | 'prop';
type ReferenceBase = {
  id: string;
  projectId: string;
  name: string;
  description: string;
  assetIds: [string, ...string[]];
};
type ReferenceDetailsByKind = {
  person: Record<string, never>;
  scene: Record<string, never>;
  voice: Record<string, never>;
  prop: Record<string, never>;
};
type CompleteReference = {
  [K in ReferenceKind]: ReferenceBase & { category: K; details: ReferenceDetailsByKind[K] }
}[ReferenceKind];
```

旧不完整资料使用独立的读取/迁移类型，不能让它冒充 `CompleteReference`。代码延续 TypeScript、Zod 判别联合、稳定 ID、服务端授权及现有项目命令风格；命名按 `reference.*` 项目操作和 `outputKind` 生成分流，不重命名现有视频 Job 身份。

### 8.2 文件与服务落点

- 正式代码只在 `InfiniteInteraction/`：`app/infinite/` 承接设定页、工坊与编辑会话，`shared/` 管契约/校验，`server/projects.ts` 与项目命令管事务，`server/generation/` 扩展图片适配与入库。
- `db/migrations/` 追加迁移，不修改已应用迁移；实际序号实施前读取，不在规格里预占。
- `__tests__/unit/`、`__tests__/integration/` 沿用 Vitest，浏览器检查使用现有可用工具，记录真实步骤/环境/截图；不宣称不存在的 e2e runner 已接线。
