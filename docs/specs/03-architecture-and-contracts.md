## 2. 架构边界

采用一个应用代码库和必要的持久任务进程，不先拆成大量微服务。

- 浏览器：画布、剪辑器、工坊和项目设定；工坊是唯一创作 AI 界面。模型管理按 08 的来源开关与个人归属控制，新密钥只提交服务端，不回读已有原值。
- 应用服务：身份与授权、项目命令、素材、生成任务、发布版本。
- PostgreSQL：项目作品草稿、设定、素材元数据、会话消息/请求卡、任务、非密钥模型配置与版本、操作记录、发布快照元数据。未发送的工坊输入和未提交表单不入库。
- 对象存储：上传/生成媒体与发布资源；CDN/可访问媒体地址供播放器使用。
- Worker：供应商提交/查询、结果入库、媒体校验、发布构建与故障恢复。
- 图片/视频供应商适配器：按输出与输入能力隔离认证、字段、任务状态、结果和错误，复用持久任务服务。

工坊调用统一应用服务，生成结果进入当前项目素材库；编辑器通过手动采用命令引用素材，不与生成侧同步场景/片段选择。断网、离开工坊或浏览器关闭不终止服务端已接受的任务。

## 3. 单一数据源

以下为实施约定，落库命名可调整，语义不得分叉。

| 实体 | 关键字段 / 约束 |
| --- | --- |
| Project | id、ownerId、title、schemaVersion、revision、graphDocument、settings；graphDocument 含 nodes/edges |
| Scene / Node | 沿用节点身份；title/bodyText；`node.data.timeline` 为唯一可编辑时间线 |
| Asset | id、projectId、type、storageKey、status、实际媒体 metadata、origin、jobId；不是供应商临时 URL |
| GenerationJob | id、projectId、createdBy、outputKind(image/video)、requestSnapshot、providerTaskId、attempt、状态、费用模式、结果 assetIds；旧任务类型与 contextSnapshot 按历史契约兼容 |
| CommandRecord | commandId、projectId、actor/source、baseRevision、参数、影响对象、结果 revision、撤销依据 |
| PublishedVersion | id、projectId、sourceRevision、immutable snapshot/manifest、引用 assetIds、构建状态、URL |
| EditorSession | 编辑器自身按场景保存选择/播放位置、画布位置、内部属性与滚动；不属于玩家作品语义 |
| ProjectReference | 公共基础＋分类扩展；person/scene/voice/prop 的完整设定有 name、description、至少一个同项目有效 assetId；旧 other/不完整资料独立兼容，详见 06 |
| Conversation / Message | projectId 下 P0 一段会话；messageId、clientMessageId、sequence、role、内容、requestId/jobId 引用；不复制任务结果 |
| GenerationRequest | requestId、projectId、conversationId、messageId、版本、outputKind、有效输入、可选显式 referenceSnapshot、固定模型/来源/凭据版本、按模式的 estimate、状态、jobId |
| ModelConnection / Provider | 按 07/08 分开供应商与模型版本、个人归属或内置 adapter 来源、能力、用户/输出类型默认、credentialRef 与审计；不属于 Project，历史配置冻结 |

不要建立“视频列表时间线”“玩法版本”“AI 项目版本”与 NodeTimeline 并行同步。时间线保存 assetId 引用；运行时所需 src/poster 从素材引用解析/发布生成，不把易过期的签名 URL 作为素材永久身份。

媒体文件内容不可原地覆盖。替换指向新的 Asset，旧 Asset 继续被历史候选或发布版本引用。删除素材需先检查草稿与发布引用；P0 不提供可能破坏已发布作品的永久删除捷径。

设定和生成快照同样参与素材引用保护；设定关系需求已撤销，迁移 026 删除关系表及命令关系快照列，旧 ZIP 的关系元数据忽略。新建必填校验不全局套给旧 `document.references`，否则会阻断旧项目无关命令。新增分类、legacy 兼容和事务迁移详见 [06](06-reference-library-and-image-generation.md)。

已有 `scope` / `contextSnapshot`（包括历史执行所需非 UI 元数据）仅在历史读取与任务恢复所需边界兼容，不据此向新工坊输入注入选中场景、片段、时间线或播放位置，不重写已确认任务或清空既有数据。

云端 project schema 与 timeline.version 是两个不同版本维度。导入旧 OpenFMV 文件先备份、执行明确迁移并校验；不借云迁移复活 legacy node.video 等字段。现有 NodeTimeline v2 可保留，不为 AI 外层任意升级其版本。

## 4. 项目命令契约

人工编辑和生成结果采用通过统一的受限应用命令执行。

命令信封至少包含：

```text
commandId, projectId, actor, source,
baseRevision, commandType, targetIds, payload
```

服务端派生/校验 actor 和项目权限，不能相信客户端声明。执行步骤：授权 → 幂等检查 → schema 与资源校验 → revision/目标校验 → 原子提交项目和命令记录 → 返回新 revision 与影响摘要。

必需用例包括：新增/修改/删除场景、连接出口、调用时间线编辑命令、配置互动、插入素材、替换片段、编辑项目设定、撤销/重做。模型配置走 08 的独立个人配置操作，不混入项目命令。场景选择与单纯播放不制造工程 revision。

客户端可做乐观预览与合并连续拖动，但服务器是持久化真源。同一项目两个标签页冲突时，拒绝静默覆盖；提供刷新/重新应用或导出本地未保存改动。单人项目不等于没有并发问题。

### 4.1 项目生成与手动采用分开

新生成请求固定所属 projectId、outputKind、作者明确填写的描述/参数、参考 assetIds 与摘要、模型来源/执行版本和费用模式。显式选择设定文件时才另固定 referenceId/版本、名称、选中文件摘要与纳入的文本，用于输入溯源。不能默认上传整个项目、全部聊天、全部素材或其他设定。

任务完成只创建项目结果素材。采用时作者明确选择同项目目标；命令必须携带目标身份、baseRevision/相关内容指纹及 commandId，重新检查目标存在性、媒体与时间线变化。无关 revision 变化可在确定未影响目标后继续；目标冲突则显示差异并让作者重新指定，不自动改别处。采用命令必须执行权限、并发和幂等校验。

从图片结果“存为设定”也是显式幂等项目命令，不由 Worker 写设定。待确认卡的设定输入失效需重新确认；已提交任务只读取被冻结且受保护的 Asset，不动态展开最新设定。删除设定不取消已提交任务。

### 4.2 修改与撤销

插入/替换必须原子提交素材引用与影响标记。按钮结果出口在图模型中保持唯一权威关系，Inspector 与画布读写同一关系；具体映射先核对 OpenFMV handles/runtime，不新增互相覆盖的目标字段。

可保留 interaction 与相关媒体 clip 的关联元数据来计算影响，但它不是第二份时间线。时间线操作移除片段、改变时间或构图时检查关联及时间覆盖范围，只报告可能受影响互动。

撤销只恢复项目编辑，不撤销对话/请求记录、已发生的供应商消耗、素材入库、模型配置或发布。撤销也走 revision 校验，不能覆盖后来的编辑。原素材不足以恢复时明确失败，不假装成功。

## 5. 生成服务

### 5.1 统一协议与受权管理配置

业务协议提供 capabilities、estimate、submit、getStatus、可选 cancel 及结果获取。领域请求使用画面描述、参考素材、期望时长/画幅、任务身份，不依赖供应商具体 payload。

供应商 endpoint、模型、认证与能力按 07/08 由服务端内置 adapter 或个人通用配置维护。来源开关为 false 时只开放内置目录；为 true 时仅可管理和执行本人配置，不回退内置。新密钥经 TLS 写入服务端加密保管，读取仅返回已配置状态，不向工坊目录、日志或错误泄露原值。

内置 adapter 声明稳定身份与版本，活动注册和历史执行注册分离；个人配置以数据库版本为真源。部署配置不反复覆盖个人页面修改，密钥只以环境变量/secret 或加密引用保存，不提交原文。来源、能力、模型/供应商/凭据与 adapter 版本在请求确认后冻结，历史缺版本不得改用最新版。

通用 JSON 配置按 07，内置模型能力和个人来源按 08，费用按 09；02 的 CN/MR 继续约束当前输入和多参考图行为。协议能力不能由模型名称猜测，内置多文件 multipart 不代表个人通用 JSON 自动支持该能力。

### 5.2 持久任务状态

```text
queued → preparing → submitting → running → ingesting → succeeded
           ↘ queued（提交前租约过期，可安全重排）
           ↘ failed（提交前校验失败）
queued/preparing → cancelled
submitting/running → cancel_requested → cancelled 或恢复真实终态
```

任一处理阶段可产生可恢复/不可恢复错误；`preparing` 尚未向供应商发起 POST，租约过期可重排。越过提交边界进入 `submitting` 后，超时且不知供应商是否接受时标记“提交状态待核实”，先查询/对账，不直接再次付费提交。

- 确认请求与创建唯一 job 需原子化；新 `estimate_only` / `none` 任务不检查、预留或扣减旧额度，历史 `legacy` 继续按冻结规则处理。Worker 持久化 providerTaskId 并使用租约/锁防止重复执行。
- 供应商支持幂等键时传递稳定键；不支持时保留不确定提交状态，避免假称全链路 exactly-once。
- 供应商成功但对象存储入库失败：只重试下载/入库，不重新生成。
- 同一结果重复回调/轮询只能创建一次对应 Asset。
- 不支持取消时说明“无法停止供应商执行”，可以停止后续采用，但不能谎称取消成功或保证不计费。
- 显式重试需新请求确认，内置按适用规则展示预估，个人不展示费用；不自动延续旧收费授权。失败分类至少含认证、限流、内容限制、供应商失败、超时/未知提交、入库失败；历史额度错误保留原解释。
- UI 不显示不存在的进度百分比。刷新从服务端读取同一 job，不重发创建。

### 5.3 结果入库

结果写入项目对象存储并核验 MIME、文件可读性、实际分辨率及适用的时长/播放兼容性；图片另核验实际解码、像素/字节资源上限，拒绝损坏或主动内容。可生成缩略图，只有 Asset ready 才展示“可采用/存为设定”。输入期望参数不能代替实际媒体 metadata；按 Job＋结果项固定 Asset 身份，重复入库不重复生成。

上传和生成最终进入同一个 Asset 模型。工坊历史与项目素材库查询同一 Asset/Job，不做二次拷贝。任务支持串行或受限并发执行。

## 6. 云端与发布

全部项目读写、素材签名、任务、采用命令和版本创建都做 owner 级授权。对象默认私有；发布只开放被选版本所需资源，不公开整个项目桶、来源描述或供应商凭据。

发布流程：确认 sourceRevision → 校验可达作品 → 固定不可变快照 → 解析素材引用与生成 manifest → 构建/上传 → 健康检查 → 原子标记 ready 并返回版本 URL。构建失败不发布半成品，不改已有版本。

预览和发布使用同一时间线编译与共享运行时。云发布不能直接调用依赖桌面文件路径的 Electron 流程；可复用资源收集/清单/播放器生成逻辑，经 Web 适配处理。无需把互动作品渲染成一条合成视频。

只校验引用资源，未采用任务不阻塞发布。硬错误包括缺入口、必需出口失效、素材不可读、互动越界/含糊重叠。媒体替换后的区域待核对属于发布前必须处理项，但不阻止草稿保存。

新任务费用以 09 为准：内置 `estimate_only` 只计算产品消耗预估，个人 `none` 不计算或展示价格；均不操作旧项目额度账户/流水。预估不是供应商实扣，生成开关、并发、所有权及紧急停用继续有效。历史 `legacy` 任务保留原预留、实扣或 `approved_ceiling` 内部记账语义，历史运维对账不通过浏览器开放，也不能用于给新任务扣费。

## 7. 最低安全与可靠性要求

- 密钥不进前端 bundle、项目下载、日志和公开版本；08 开启个人配置时仅本人可提交自己的凭据，不回读已有原值。来源开关、登录身份及个人归属在服务端检查，不依靠已移除的管理员角色或隐藏按钮。
- 上传及生成下载限制类型、大小和时长，处理损坏文件；供应商结果下载与配置 Base URL 均限制可信来源，拒绝生产回环/私网/链路本地/元数据地址并检查解析结果、重定向、DNS 重绑定及出站策略。原型允许 localhost 不是生产网络许可。
- 对模型输出、原文和文件名按不可信内容处理，渲染转义，不执行生成脚本。
- 自动保存、采用、发布都能显示真实失败；本地恢复副本仅用于救援，不与云草稿竞争为真源。
- 记录 commandId/jobId/projectId 与错误类别用于诊断，避免记录密钥或无必要的全文内容。
- 备份与 schema 迁移先覆盖测试，不做隐式不可恢复更新。

## 8. 对话与请求确认契约

### 8.1 三种状态分开

对话消息记录用户输入与解释；GenerationRequest 记录待批准的图片/视频请求；GenerationJob 记录外部执行。三者不能共用一个任意改写的草稿对象。

```text
消息：sending -> stored / failed
请求卡：pending -> submitted / superseded / cancelled / expired
任务：沿用 5.2 的持久执行状态
```

正式请求整理至少输出所属项目、显式描述、参考 Asset 与支持参数。按 CN，新提示词原样冻结，历史 compiledPrompt 保持；不恢复已删除的 @ 自动编号/引用编译。仅外发作者确认的描述与参考输入。

clientMessageId 在项目会话内幂等，服务端派生角色与顺序号。用户不得通过传 role=assistant 或伪造 requestId 获得执行权限。消息确认、任务轮询和时间线修改相互独立；发送失败保留当前组件输入及本次提交标识并提示，不显示为已保存。响应丢失后的原地重试复用相同标识。

### 8.2 提交事务

1. 作者确认指定 requestId/requestVersion；前端双击禁用只改善体验，服务端仍需幂等。
2. 校验项目权限、pending 状态、参考素材归属与可用性、显式设定快照、来源/配置版本及能力；内置校验预估期限/规则，个人不受价格或估价期限限制。新任务不校验旧余额。
3. 单个事务将请求置为 submitted、创建唯一 job 并记录关联；requestId 上唯一 job 约束，重传返回同一任务。新任务不预留额度，历史确认重放仍返回原任务。
4. 有效输入、参考资料、模型/供应商/凭据及执行版本、费用模式固定到任务，不从当前 UI 输入或编辑选择重新读取。
5. 更新描述使旧 pending 请求 superseded，并产生新请求版本。提交与替代并发必须原子裁决；若任务已接受，后续编辑只能产生新请求，不能“替代”已运行任务。
6. 适用的预估到期、来源或配置版本失效时要求重新确认，不静默换模型、输入或费用模式；个人任务不因缺价格拒绝，详见 09。

请求卡渲染读取 jobId 对应的实时状态；状态更新不创建重复消息，工坊对话和历史引用同一记录。旧原型中没有 message 的任务可在历史查询，不强制伪造用户发言。

### 8.3 对话持久化与采用

每个项目一份 Conversation；仅消息、请求卡和任务持久化。未发送输入在当前工坊组件内维护，图片/视频共享提示词并分别保存本次页面会话中的模型、参数和参考素材；编辑器选择不成为工坊输入。不同浏览器标签不共享未发送输入，消息发送、请求确认和采用仍须幂等，不能重复提交。

对话只外发确认卡列出的描述和参考输入，项目设定、模型管理表单、密钥和无关会话不默认外发。生成结果由 Asset 管理，删除/折叠消息不影响媒体引用。P0 不做对话删除、会话分叉或聊天附件独立素材库。

## 9. 模型配置执行边界

- 配置保存及离线预览不隐式调用付费接口。启用、默认、凭据状态、协议支持与实际可用分别表示；个人配置的浏览器权限及来源门控以 08 为准，不保留旧管理员专属规则。
- 个人默认按用户及输出类型唯一，设默认和停用须事务化。优先校验显式选择的兼容模型；仅未选择且无同类型可用默认时阻止新请求，上传编辑仍可用。来源切换不回退其他目录、不影响运行任务版本。
- 通用配置使用 07 的受限 JSON 模板及校验，不执行脚本；凭据、出站地址及执行元数据不能从创作输入覆盖。内置 adapter 按 08 的固定版本执行，个人协议不因内置能力更新自动改变。
- 配置更新生成新版本，提交任务保存非敏感快照与凭据版本引用。运行中任务继续查询原服务；必要凭据轮换只在明确策略下更新，不自动换 providerTaskId 所属服务。
- 停用只阻止新提交，不等于取消外部任务。存在活动任务的配置不能物理删除；先停用，待任务结束后归档。保留审计与非敏感历史，密钥按轮换/保留策略处理。
- 配置写入记录操作者、时间、ID/版本和字段类别，不记录 Key 原文。用户仅可管理自己的个人配置；工坊目录不返回协议、地址、请求头或 credentialRef，内置配置不通过个人入口修改。
- 原型的独立 localStorage 元数据和内存 Key 仅作 UI 参考，不自动迁移为生产凭据，不写入 PostgreSQL Project/发布快照。
