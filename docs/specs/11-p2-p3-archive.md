## 4. 执行步骤与前置门禁

### A. 冻结与安全预检

1. 保存当前已有 dirty/untracked 状态，不执行 reset、checkout、提交或推送。
2. 用显式允许清单盘点，保存每个待归档原件的哈希和元数据，并记录需要删除的目录。空目录一并记录。
3. 检查磁盘空间，至少保留 10 GiB；检查活跃写入和敏感材料风险，必要时协调写入者。构建/测试不得污染当前开发 .next 或既有用户数据。
4. 备份允许适配的在用文件；源材料如在归档或删除前发生变化，中止相关操作并重新冻结，不删除新内容。

### B. 解除必要引用

1. 原 OpenFMV/sample-projects/rainy-night-call.openfmv-project.zip 作为 P3 完整归档后删除，不复制到正式应用。
2. 按用户授权删除仅依赖该 ZIP 的单条测试及 readFile 专用 import，保留另外四项导入测试原文。记录覆盖范围减少一项，原测试完整版本收入 meta/changes；不把用户撤销的测试伪称为迁移通过。
3. 经授权，移除 package.json 中废弃的 main: electron/main.js 声明；不改变 dev/build/start、依赖或 Worker 入口。
4. 对仍保留文档中的归档路径建立可点击的 P1 归档索引条目，列出包内原路径及恢复方法。保留历史原文含义，不改写任务完成状态。内部已归档文档之间的相对路径由原目录结构保留。
5. 对 P3 候选重新检查运行入口、配置、动态资源路径和测试引用。必要的 P0/P1 依赖不得因清理被删除；发现真实冲突则记录并解决或请求用户决定。

### C. 隔离移除验证

在新的临时验证目录复制正式应用，排除待归档文件，不使用历史项目目录，不运行历史项目代码。

- typecheck、lint、全部单元测试、全部集成测试、生产 build 必须通过；已存在的可选跳过如实记录，不增设跳过。
- 集成测试使用独立测试数据库和隔离存储边界；不修改现有用户、项目、配置或预算。
- 本地 HTTP/浏览器冒烟覆盖登录、项目列表、故事画布、工坊、素材、设定、发布/试玩的可达性及关键读写；无真实供应商请求。
- 特别验证剩余四项旧工程导入测试完整通过，且验证目录不存在 OpenFMV 目录；媒体/导出/发布等既有回归不受影响。全量集成预期由 185 项通过减少为 184 项通过，保留 1 项既有可选跳过。
- 静态编译无错误不足以单独支持删除结论。所有失败先定位；属于本次移除导致则修复并重测，不能忽略。

### D. 打包、恢复验证

1. 生成唯一临时包；输入只来自冻结清单和 meta，排除产物自身。
2. 压缩流完整性验证通过，包内路径唯一、无绝对路径/路径穿越，无意外成员；符号链接不解引用。
3. 解压到新的隔离目录，不覆盖工作区、不运行其中脚本。全部文件逐项核对哈希、类型、权限和链接目标，目录及元数据按 manifest 检查。
4. 再次核对待删除源文件与冻结清单一致。完整通过后才批准删除；任何差异都不得通过重新生成哈希掩盖。

### E. 原件删除、收尾

1. 仅在 C/D 门禁通过且必要适配获授权后执行精确清单删除。普通文件/链接逐项核对后 unlink；目录仅从内到外 rmdir，非空则停止，绝不对 workspace 根执行递归删除。
2. 原件删除后确认清单路径全部不存在，P0/P1 保留文件除已批准适配外哈希不变；正式业务源码不变。
3. 检查保留文档链接，运行正式目录的无输出类型检查、关键导入回归及应用冒烟；必要时扩大全量回归。开发/构建不并发共享 .next。
4. 将最终验证结果收入唯一压缩包（在隔离工作区完成临时包重建并完整复核，再原子替换），记录最终 SHA-256。保留当前 P1 规格、归档索引和执行报告，不留第二份压缩包。
5. 删除仅由本任务创建且已验证不再需要的临时副本、测试数据库和临时进程；不触碰其他项目资源。执行报告列明删除范围、可恢复方式、验证结果和真实遗留项。

## 5. 回滚与恢复

失败时先保留原件或现有可恢复副本，停止进一步删除。恢复先在独立临时目录解压并验证 SHA-256，再按原相对路径恢复选定文件；不得覆盖归档后新增的同名文件。

原始代码、依赖及 .git 虽可逐字节恢复，但恢复验证不执行历史代码。适配文件的变更前版本收入 meta/changes，以支持需要时成组恢复。归档不能替代异地备份，本次不上传或另存外部副本。
