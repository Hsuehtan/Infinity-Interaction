# 04 · 实施顺序与验收

版本：1.2 · 本期范围修订：2026-10-04 · [返回规格入口](README.md)

本文件定义独立工坊、手工编辑与发布的验收要求，不是完成报告。本期有 50 项有效 AC，沿用原编号，不补齐编号空缺；AC-45 保留原撤销记录。已有 M1/M2 签收继续有效，其他未签收项仍按实际证据验收。

已批准的 G/R/J/B/IW/E/CN/MR 增量继续有效，模型配置、来源权限与新任务消耗语义分别以 [07](07-generic-model-configuration.md)、[08](08-model-source-modes.md)、[09](09-model-consumption-estimates.md) 及其后续修订为准，不恢复旧的单一适配器、管理员唯一配置或新任务额度预留限制。

## 1. 实施策略

每个阶段交付一条可演示路径。先建立不用 AI 的创作闭环，再接通独立工坊的素材生成，完成可用性与发布。工坊新生成只绑定项目及明确输入的文件/参数，不绑定 scene/clip、不读取编辑器选择；结果仅入项目素材库，采用时再手动选择目标，并校验指纹、revision 和幂等。沿用现有组件和时间线命令，不先重构整个 OpenFMV。

不在这里给出未经人力与技术验证的日期承诺。遇到范围扩张回到 [01](01-product-scope.md)，不能通过“顺便支持”增加 P0。

| 阶段 | 工作与产物 | 退出门槛 |
| --- | --- | --- |
| M0 基线与迁移设计 | 记录实际源码/工作树；复跑 lint、测试、build；核验按钮、QTE、音频、Web 运行链路；锁定云存储/身份方案 | 存量失败明确分类；核心编辑/试玩可复现；旧文件迁移样例可验证；不覆盖用户改动 |
| M1 无 AI 编辑闭环 | 项目首页和权限；PostgreSQL 草稿；上传到对象存储；画布进入剪辑器；模板、结果、预览、分类设定；统一命令与撤销 | 不打开 AI，能够完成并重新打开一份含分支的可玩草稿；双标签冲突不丢数据 |
| M2 真实素材生成闭环 | 选择并验证一个视频适配器；管理员模型配置与密钥托管；额度、持久任务、结果入库；工坊对话/请求确认/历史/采用 | 真实视频可生成、入库、插入、替换；重启恢复；不确定提交不重复计费；使用记录可查 |
| S1 设定与图片生成增量 | T64–T76、T78：按五个交付包完成多文件设定、文生图/参考图生图、快捷建设定及显式引用；复用 W01–W06 | AC-43～52（AC-45 已撤销）、AC-54 工坊/设定部分有证据，纯上传与图片→设定→视频路径通过；新增真实调用独立授权，不重开 M2 |
| M4 工坊可用性与 Web 发布 | T79 已完成本地入口与旧 UI 状态清理；T46–T48 的键盘、请求并发及编辑可达性历史签收保留，持久草稿要求已撤销；T49–T57 完成固定快照、资源授权、共享运行时与发布 | 独立工坊可生成和手工采用；两条路径在本地发布成功，旧版本不随项目作品变化；本期有效 AC 通过 |
| M5 小规模创作者验证 | 受控素材测试编辑器；单独测试内置生成；记录阻塞、采用和返工 | 输出真实观察与决策，不把功能完成视为产品价值已证明 |
| M6 生产部署与快速验收 | 将本地验收版本部署到生产服务器；恢复凭据、配置网络与持续 Worker；快速复核核心路径，不开发新功能 | 部署可运行、可回滚，生产安全与功能冒烟有证据 |

M2 只以本地环境的真实供应商调用和功能/安全验收退出；生产 secret 恢复、出站网络策略和部署后 Worker 恢复均归 M6。M6 的新增付费调用需要当时有效的独立预算。

当前交付路线为 **M2 → S1 → M4 → M5/M6**，保留任务及检查点原编号。S1 保留 14 个编号，其中 T67/T68 撤销、12 项有效任务仍按五个交付包推进：设定库 T64–T66、图片服务 T69–T73、工坊图片 T74、衔接 T75–T76、收尾 T78。上传/设定可独立交付；T78 不依赖 M4 T50，AC-54 发布隔离仍由 T50/T57 补齐。

T46/T47/T48 在 M4 验收普通工坊及编辑器的必要可用性，C16 为工坊可用性检查。T79 已完成本地入口与旧界面状态清理，其有效验证证据可复用；普通工坊共用能力、历史请求/任务/参数继续保留。T57 汇总 T79、T48 等本期任务的有效证据，未签收项不得据此自动关闭。

原型界面必须标记模拟服务，不能代替本期上传、生成、采用与发布的真实链路验收。

## 3. 工程验证层次

1. 单元测试：时间线命令、几何/时间边界、QTE 状态、模板映射、不可变请求输入、采用冲突、撤销及新旧任务消耗语义。
2. 集成测试：PostgreSQL revision 与幂等、项目所有权、对象存储引用、Worker 恢复、重复回调、结果入库、发布快照固定。
3. 浏览器测试：本期 AC 主要链路、工坊键盘/输入生命周期、错误定位、手工采用、入口收敛后内部属性可用；320/768/1024/1440 宽度基本操作可达。
4. 真实供应商冒烟：用明确预算、授权素材和最小请求验证提交、查询、下载、错误及实际用量。测试替身不能代替真实生成验收。
5. 播放器验证：至少覆盖支持范围内桌面浏览器与真实移动端触摸；移动端自动播放/音频限制按实际行为测试，不只模拟鼠标点击。

特别覆盖媒体实际结束时间与时间线四舍五入不完全一致的情况，避免视频已经结束但场景/试玩仍等待几毫秒而不结束。

所有运行结果记录执行日期、源码 revision、环境、通过/失败、存量问题与新回归。文档中不预填成功数量。

S1 的执行真源为 [plan §7「S1 增量验证与证据复用」](../../tasks/plan.md#7-完成标准与验证执行)：单项做定向 U/I/E，C22–C26 审查证据并补新增连接处回归，不逐任务或检查点重复全量构建；T78 在最终冻结修订统一执行一次适用全量检查与核心路径集成演示。未变化页面复用四尺寸/IME 证据；证据需绑定源码/dirty hash、依赖、配置、环境和测试数据身份，受影响变更使证据失效并要求重跑，高风险变化及时扩大回归。同一有效真实调用证据可跨任务引用，不重复付费证明同一事实；真实授权、权限、防重复收费和媒体验证等底线不变，模拟仍不能代替真实验收。

## 4. 产品验证设计

### 4.1 先隔离编辑器价值

建议招募 5–8 位符合目标画像的创作者作探索性测试，而非声称具备统计代表性。测试任务和观察流程需在招募前确定，不在看到结果后改变成功定义。

提供同一套授权的视频素材与已明确的故事关系，让参与者完成普通选择、一个 QTE、一次换片返工及发布。与直接使用 OpenFMV 的等价任务对照；采用任务配对或交叉顺序，避免练习效应被当作产品优势。

记录：独立完成率、求助/代操作次数、关键操作耗时、返工耗时、失败位置、实际试玩错误、是否愿意用它做下一个作品。讲解和开发者代操作需计入，不隐藏在“少量协助”里。

### 4.2 再验证生成衔接

使用同一供应商/相近生成设置比较内置生成与外部生成后导入，尽可能控制内容差异。记录端到端耗时、搬运操作、重试次数、结果采用比例、获得可用素材的成本以及换片返工。

“已生成”不等于“有用”：实际采用进入时间线且在试玩作品中保留，才记为采用。视频审美/叙事适配由作者及盲看反馈评估，与服务成功率分开报告。

### 4.3 短作品与决策门槛

实施约定：第一轮使用约 3–5 分钟单路径、至少一个分支、至少一个 QTE 的短作品验证闭环；这是测试样例，不是产品场景数、时长或题材上限。

功能发布门槛：P0 必需链路通过、无已知数据丢失/越权/重复计费高风险缺陷、真实上传/生成/采用/发布可重现。

产品判断不预造成功比例：测试前结合 M1 基线确定目标耗时和可接受求助水平，记录并锁定。结果若显示作者主要卡在手工编辑，先修编辑器；若外部生成导入同样方便，不能据此宣称工坊差异化成立；只有明确重复劳动及可评测收益，才启动下一项 AI 操作。
